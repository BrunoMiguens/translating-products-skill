# Native translation verification

The follow-up checked the integrated skill against the [25-project baseline](native-quality-baseline.md). It replayed approved setup for all 1,519 archived scopes and rerouted 969 saved requests. The 25 selection changes added the RTL specialist to the expected requests.

Fresh translation trials used matched English inputs and approved project context. Publisher wording and contributor evidence stayed outside the translation workspaces. The selected trials cover diagnostics and controls.

## What passed

- **Separate localized documents.** An Ethereum.org run overwrote two English files. After the source-preservation change, five sessions delivered nine translated Markdown and AsciiDoc excerpts at separate paths. All retained the English files and passed the exact review-to-delivery checks. [Source-preservation fix](https://github.com/BrunoMiguens/translating-products-skill/pull/9)
- **Android resource lookup.** On Android API 36, 84 selected lookups returned English at the original Hebrew paths. The same values resolved at the legacy qualifiers. One integrated run still reported success at the wrong path after reading the revised guidance. The saved-resource check now rejects that directory before delivery, including when runtime UI review is skipped. Publisher layouts and intentionally missing keys served as controls. [Android qualifier fix](https://github.com/BrunoMiguens/translating-products-skill/pull/11)
- **Native resource checks.** Both date-fns arms compiled in the pinned consumer fixture. Each passed 13 API checks with Date and timestamp inputs and matched all 97 selected values to the delivered modules. Flutter and Apple checks each exercised 12 values per delivered arm. WordPress plural checks covered the selected GNU libintl and Python gettext consumers.
- **Four regional fixtures.** AppFlowy onboarding, npmx marketing, Yoast marketing and the Jellyfin Play Store title each matched the export to the native file. Both Latin American Spanish title drafts used 29 of the 30 allowed characters.
- **Source-locale authority.** The project order test reproduced a false conflict after the agent gave an English request the exact tag `en`. The corrected four-turn replay delivered all 12 selected values without changing the other project or earlier locale files. An explicit conflict still withheld output. [Source-locale fix](https://github.com/BrunoMiguens/translating-products-skill/pull/10)

## Linguistic acceptance

The private evaluator holds the masked comparisons and exact publisher evidence. Eight Arabic plural units from the initial gbrainy comparison are excluded because the export represented only one form per unit while the native catalog contained all six. A separate same-request rerun matched all 12 selected units to the compiled catalog, including every plural form. A human-quality claim needs qualified bilingual review and agreed acceptance thresholds. Full-app verification outside the scoped fixtures remains open.
